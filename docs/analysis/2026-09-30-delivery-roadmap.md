## 1. 如何把建议转成执行

采用三层组织：

1. **路线图**确定用户结果、优先级、依赖、完成门和暂不承诺的内容。
2. **单项 Plan**锁定一项可独立验证的行为，写清当前证据、改动范围、任务、验收、规范增量和回退方式。
3. **实施与复审**在独立工作树执行，以真实文件、两条渲染轨和测试证据验收，通过后合入并沉淀规范。

每次详细化下一项；后续需求保留稳定的候选编号 R-xx，正式立项时再分配 PLAN 编号。避免提前占号、空计划和对未解锁技术作虚假承诺。

初始规划只创建路线图和一个详细 Plan：[PLAN-030 安全重载](../plans/archived/030-safe-manual-reload.md)；该次规划没有实施代码。后续交付状态见本文件顶部进度更新。

## 3. 必须单列的基础调查与供给

| 调查 | 具体产物 | 允许的出口 |
| --- | --- | --- |
| T-规模正确性 | 200/500 页原文、页面、链接与搜索结果对照；复现 VM 值损坏；可用载体和根因证据 | 已修复并验证 / 可行替代承载方案 / 上游 blocker；后两者不能宣称规模达标 |
| T-接口能力 | vm/vue 对 command/save/link/cursor/selection/reveal 的已支持、已接线、缺供给清单 | 本仓消费 Plan 或明确上游供给要求；不把已有 Vue emit 当 VM 可用 |
| T-保存协议 | 草稿格式、原子替换、修订检测、迟到回执、同秒写入与恢复规则 | 小语料原型与决策稿通过后实施；mtime 单独使用不足 |
| T-工作区 | 根路径设置的运行期行为、状态隔离、切库时脏页、打包路径 | 运行期切库方案或重新启动到指定库方案，说明限制 |

每次调查绑定一个问题和明确决策，不以“继续研究”作为结束。单项默认一次原型加一次复测；若仍无法判断，写出缺失证据、负责模块与重入条件，由下一次授权确定是否继续。这里是建议调查边界，不是用户指定的时间或 token 预算。

上游/兄弟仓只读调查可用于规划；修改需在各自明确的实施范围内进行。本次没有授权跨仓写入。

## 4. 单项计划必须包含的内容

延续 auto-plan 的 0..10 节与 metadata：

- 当前行为与已同意规范：使用实际路径、符号、版本或 hash。
- 用户能观察的目标、非目标、依赖与边界。
- 实施设计与失败/取消/并发/兼容语义。
- T-xx 任务，每项关联 AC-xx；调查任务给结论出口。
- 测试与验收，正文/磁盘/投影/导航分别留证据。
- SD-xx 规范增量；PLAN-030 已新增 docs/specs/editor-safety.md，后续优先读取相关局部规范，其他约束继续引用 ARCHITECTURE，不做整套文档迁移。新阶段只提议规范增量，实施时再落位。
- revision 与复审记录；改目标、验收、兼容承诺或跨仓范围需要先修订契约并处理相关授权。

## 5. 每项的执行循环

1. `auto-plan-new`：详细化并检查任务、验收和依赖覆盖。
2. `auto-plan-work`：取得该项执行授权后，在专属工作树实施；主检出保存 Plan 进度。
3. 先跑有意义的目标验证，再跑受影响回归；测试结果绑定代码 revision 和工具链载体。
4. `auto-plan-review`：独立复审实现、AC 与 SD；给 pass / needs_fix / needs_replan / blocked。
5. needs_fix 回工作阶段；needs_replan 修订计划；blocked 保留证据和重入条件。
6. `auto-plan-merge`：复审证据与代码 revision 一致后合入、沉淀规范、刷新索引、归档并清理工作树。批回归到期时按既有规则处理。

计划完成不能仅以页面截图或测试数量判定。未保存正文保护必须看到正文与磁盘不丢失；查找必须用名称不同的已知样本；迁移必须做往返；上游限制要如实保留。

## 6. 里程碑与排期

| 工作门 | 面向用户的完成标准 |
| --- | --- |
| M-A 可信试用 | 核心操作一致，误重载受保护，草稿可恢复，显示名称可找回；首启与交付范围如实说明 |
| M-B 日常知识库 | 能可靠记录、整理、检索、引用、恢复和导出；小规模真实用户持续试用 |
| M-C 组织与规模 | 类型视图/引用有使用价值，宣称规模通过正确性与性能验证 |
| M-D 跨设备或生态 | 按具体产品方向分别验收，不能把各项都绑成一次发布 |

这些是工作门，不自动改写现有 v0.1.0 判据，也不预先分配 v0.2.0/v0.3.0。版本、发布日期、开发容量与每轮自动继续范围在相关发布或执行指令中确定。

排期先估相对体量和依赖，做完首项后用实测工时校准。报告中的性能数字保留为待建立基线的目标，不直接写成所有后续 Plan 的硬门。

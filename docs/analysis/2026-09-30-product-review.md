# jade-edit 界面与功能修改建议

日期：2026-09-30。分析基线：仓库 `9ab1b57`、v0.1.0 试用就绪文档、当前 `src/front` / `src/back`，以及本地启动的 Vue 界面。本报告是产品建议，不改变既有 Specs，也不是已批准的实施 Plan。

## 1. 核心判断

jade-edit 已经有个人 wiki 的基本功能骨架。下一阶段的主要任务是把这些功能组织成可信、流畅的知识工作流程，同时解决承载边界。建议定位为：**面向中文个人用户，以本地文件为基础、适合长文写作，也便于持续积累和引用的知识库。**

保留文档为主要编辑单位。吸收 Logseq 的每日记录、上下文反链、逐步整理；吸收 Obsidian 的链接导航、文件自主性和多种组织入口；吸收 Notion 的属性与筛选视图。不要在当前阶段同时承诺完整的块数据库、团队协作、全能项目管理。现有架构也已把 Notion/飞书协作放在远期。

优先级原则：数据可信 > 高频操作一致 > 写作与检索闭环 > 组织与复用 > 探索展示。图谱、AI 和插件生态需要有实际场景，并以可靠数据和清晰接口为前提。

## 2. 证据与分析边界

实际检查了 Vue 的空态、文件树、首页编辑页面、快开和反链面板。复现了“树和标签页显示首页，但快开输入首页没有结果”。运行语料是单独复制的测试工作区，未使用用户真实知识库。本轮没有重新测量性能，也没有对原生 VM 界面做视觉验证。

以下区分三种证据：

- **界面实看**：当前 Vue 显示的布局和交互。
- **代码确认**：当前处理逻辑或接线可直接确认。
- **既有记录**：发布说明、架构与基准测试已有结论；不等于本轮重新验证。

具体修改建议和性能目标都是提案。没有用户试用数据的项目，需要用短周期试用验证价值，而不是凭竞品功能数量判断。

## 3. 用户需求：以工作流程衡量功能

| 主要场景 | 用户真正要完成的事 | 产品应提供的闭环 |
| --- | --- | --- |
| 随手记录 | 先记下来，再决定放在哪里 | 今日笔记/收件箱 → 自动保留草稿 → 标记待整理 → 转正式页面 |
| 长文写作 | 稳定输入，集中思考，引用资料 | 大纲 → 专注写作 → 引用/预览 → 返回原位置 → 安全保存 |
| 学习与研究 | 累积来源，形成自己的解释 | 剪藏/附件 → 来源属性 → 摘录 → 主题页面 → 上下文反链 |
| 个人项目 | 把相关资料与待办放在一起 | 项目页 → 标签/属性筛选 → 简单任务清单 → 归档 |
| 查找旧知识 | 不记得文件名，也能找回内容 | 标题/别名/正文搜索 → 匹配摘要 → 直接定位 → 浏览历史返回 |
| 长期维护 | 搬动、改名、恢复时仍可信 | 导入报告 → 消歧链接 → 安全修改 → 版本恢复 → 完整导出 |

初期重点服务随手记录、长文写作和查找旧知识。研究与项目场景逐步增加能力；团队协作需要独立的权限、同步和冲突模型。

## 4. 当前能力与关键差距

| 能力 | 当前证据 | 修改重点 |
| --- | --- | --- |
| 页面关系 | 已有 wikilink 索引、反链/出链、未链接提及、提及转链接 | 正文跳转接线、上下文片段、具体位置、预览与返回 |
| 文件生命周期 | 已有页面/目录新建、移动、重命名、删除、合并与回收站 | 就地操作、批量操作、冲突结果可读、脏文档保护 |
| 元数据 | 已有 title、tags、aliases 编辑 | 页面内属性、字段类型、筛选；title 参与发现，不自动改变链接身份 |
| 查找 | 快开按路径子串；全文按 stem/aliases/body 子串；结果按遍历序截断，前端传 20 | 显示标题与别名一致匹配、命中高亮、排序、分页、过滤、定位 |
| 每日笔记 | 已有幂等建页，根目录固定日期名与模板 | 日志专属目录、模板配置、历史日期导航、待整理入口 |
| 最近打开 | 已持久化，容量 10 | 收藏、浏览返回、标签页/滚动/面板状态恢复 |
| 保存与恢复 | 手动保存、脏标签页关闭确认、退出确认、回收站 | 草稿恢复、版本历史、自动保存、外部编辑冲突 |
| 工作区 | 通过环境变量选择；源码自建自用，没有独立安装包 | 首启创建/打开知识库、最近知识库、打包、设置 |
| 规模与编辑 | 发布说明保留 P≤200 稳定范围；整文编辑回传依赖上游 | 修复上游承载问题、增量事件/索引、分层测量 |

需要特别重视的具体问题：

1. **可见操作与真实行为不一致。** `EditorStore.ActUndo/ActRedo/ActCut/ActCopy/ActPaste/ActSelectAll` 目前仅写日志。编辑器本身的快捷键可用，不能据此判断菜单操作有效。应接入统一编辑命令接口；在接口未具备时，移除或禁用无效入口并说明原因。
2. **重载存在丢失未保存修改的风险。** `EditorStore.Reload` 直接读磁盘并替换 body/original_body、清空 dirty；App 的重载薄委托没有先保护脏内容。应提供“保留当前草稿／查看磁盘版本／放弃修改并重载”，并在放弃前保留可恢复副本。
3. **Vue 编辑器的事件没有形成宿主闭环。** 当前生成的 `AutoDownEditor` 只绑定 `update:modelValue`，未绑定 `save` / `open-wiki-link`；上游 EngineEditor 已发出这些事件。界面里额外的英文 Save 按钮因此不能仅凭显示就认为已接入工作区保存，正文链接也需要接入页面解析和开档。应修 DSL/生成器/适配契约，不能直接手改生成物作为正式实现。VM 支持需另行确认。
4. **名称在显示与查找之间不一致。** 测试语料 `wiki/index.ad` 的显示标题为“首页”，快开输入“首页”无匹配。全文搜索也没有消费 frontmatter title；有些页面碰巧在正文重复标题会命中，不能保证所有显示标题都可找回。修查找即可，不必把 title 纳入链接身份域。
5. **全库工具与当前页工具混在右侧。** FIND 承担文件、全文、悬空、回收站和孤页五种模式，LINKS 和 TAGS 还能叠放。多面板打开后共享滚动与窄列，任务边界不明显。
6. **非页面文件出现为无效按钮。** 当前文件树显示测试语料中的 JSON，`OpenFile` 对非 `.ad` 项走目录切换分支，成为无效操作。应区分页面、附件和其他文件，分别提供明确动作或过滤。
7. **界面继承了开发工具气质。** EXPLORER/FIND/LINKS/TAGS、ready、Console、路径形式保存结果、重复 Save 入口，以及较小的面板文字，增加新用户理解成本。调试信息应进入诊断入口，日常界面用统一的中文任务名称。

## 5. 界面方案：按全库、当前文档与当前位置分工

### 5.1 推荐默认：文档工作台

**顶栏**：知识库名称/切换入口、全局搜索、快速新建、命令入口。保留桌面菜单，但不要求用户通过“视图”菜单发现核心能力。

**左侧全库导航**：今日笔记、收件箱、收藏、最近打开；下方切换“页面 / 标签 / 已保存视图”。文件夹仍可用，但不是唯一入口。知识库维护与回收站放在下部或更多菜单，避免把健康清单当每日必做事项。

**中间文档区域**：标签页 → 浏览返回/前进与面包屑 → 显示标题 → 可折叠的页面属性 → 正文。页面动作菜单容纳改名、移动、复制链接、历史、删除。正文宽度可设，建议桌面初值约 720–840px，中文行长以约 35–45 字试调；这些是设计起点，不是通用标准。

**右侧当前页上下文**：默认收起，需要时在“大纲 / 引用 / 属性”间切换，避免全部竖向叠放。引用页签包含反链、出链、未链接提及；标签管理移到左侧，当前页标签仍在属性区域。

**底部状态**：已保存到本地 / 保存中 / 保存失败 / 草稿已恢复；需要时展示字数和索引进度。不要把索引陈旧与正文未保存混成同一个状态。正常状态简短，失败状态可点击查看原因与重试。

侧栏宽度可调、可折叠；布局跨会话恢复。在小窗口和窄屏中用抽屉或单栏切换，不能仅 `hidden md:flex` 隐去入口。专注模式隐藏侧栏与多余工具，仍保留保存异常提示和退出入口。

### 5.2 可选：日志工作台

同一知识库增加“日志”视图，按日期组织每日文档，支持上一日/下一日、日期选择、模板和快速记录。每条记录可链接主题页，也可提取成正式页面。初期仍保存为文档与普通列表，不要求立即拥有 Logseq 式块数据库。

两种工作台共享页面、保存、解析和索引；日志是使用方式而非第二套数据模型。用户可以设定启动进入上次文档或今日笔记。

### 5.3 交互规范

- 单击导航使用预览标签页；编辑或双击后固定，减少大量一次性标签页。
- 快开用居中轻量弹层，支持方向键、Enter、新标签页打开；全文搜索在左侧或独立结果视图保留上下文。
- 页面和目录的菜单绑定被操作对象；不用让用户手填现有目录路径。移动弹层提供目录选择与搜索，拖放作为后续增强。
- 普通创建与改属性就地完成；恢复、覆盖、批量替换等高影响操作展示结果预览。
- 保留已有快捷键配置以避免破坏习惯；提供可搜索、可配置的命令清单，验证与编辑器及操作系统的冲突。不为模仿 Obsidian 硬换 Ctrl+P 的含义。
- 图标有可访问名称，核心入口有文字；键盘焦点可见；错误和悬空链接不能只靠颜色区分。正文大小、行距、主题可设。

## 6. 功能方案：打通高频闭环

### 6.1 可信保存与数据恢复（P0）

先建立保存协议，再加自动保存。每个文档有 loaded_revision、编辑版本和最后成功保存版本；保存带基准 revision，用内容哈希或足够可靠的版本机制检测外部修改。已有 mtime 文档明确是秒粒度，同秒变化不能只靠 mtime 判断。

建议顺序：

1. 保存失败保留 dirty 与正文，允许重试；重载、改名、移动、批量改写、退出均统一保护草稿。
2. 本地草稿日志与崩溃后恢复；恢复预览两份内容，绝不静默覆盖磁盘。
3. 原子保存或等效安全替换；明确平台文件操作的失败与中断语义。
4. 文件级历史，支持差异预览、恢复为新副本、保留周期与容量设置。
5. 自动保存可选，建议默认开启；输入防抖、连续输入期间最大间隔、窗口失焦等触发经测试确定。Ctrl+S 仍显式刷新。写入必须排队并匹配版本，迟到回执不能把新修改标成已保存。

回收站负责删除恢复；草稿负责尚未成功保存的内容；版本历史负责已保存后的误改；备份负责整个工作区失效。四者需要清楚区分。Obsidian 的文件恢复和 Joplin 的历史机制都说明恢复能力属于日常可信体验，而不只是高级功能。[Obsidian 文件恢复](https://obsidian.md/help/plugins/file-recovery)、[Joplin 笔记历史](https://joplinapp.org/help/apps/note_history/)。

### 6.2 写作体验与宿主接线（P0/P1）

P0 修菜单命令、编辑器保存与正文链接。P1 统一阅读/实时编辑/源码查看模式、选区工具、文内查找替换、标题大纲与定位、专注模式、光标与滚动恢复。保留共享编辑器内核，将通用编辑能力交给 auto-edit/AutoDown，上层知识库界面和数据行为由 jade-edit 消费。

中文输入、中文标点、中英文混排、组合输入撤销、表格粘贴和代码块编辑作为真实场景测试。上游已有事件并不等于两条渲染轨都能消费，需为 save、command、link、selection、cursor、reveal 建立逐项能力表。

### 6.3 查找与导航（P0/P1）

P0：快开同时匹配显示标题、文件名、相对路径、别名；全文补显示标题。结果展示标题 + 父目录，精确匹配优先；没有结果允许直接新建。title 的发现功能与链接解析语义独立。

P1：匹配高亮、多条摘要、总命中数/分页或渐进结果，支持标签、目录、修改时间、类型筛选；先给可视筛选，不要求用户学习查询语言。保存常用查询为视图，进而承载待整理、项目资料和任务清单。中文搜索先保证连续子串与中英混合可用，拼音/首字母匹配待用户反馈后加入。Joplin 官方文档特别指出 CJK 与拉丁词边界不同，搜索实现不能直接照搬英文分词假设。[Joplin 搜索](https://joplinapp.org/help/apps/search/)。

结果点击应定位正文匹配处；上游 reveal 未接通前如实提供开页，不把“打开页面”写成“定位完成”。浏览历史同时保留路径、位置与视图；关闭标签页可以恢复。

### 6.4 链接与引用（P0/P1）

正文 `[[` 候选补全、选择文字转链接、悬空目标建页、悬停/快捷预览、原标签页或新标签页打开构成一条流程。先接入已存在的页面解析，再增加标题锚点和稳定块标识。

反链按来源页面分组，展示命中段落与前后文；点击定位，允许右侧打开对照阅读。未链接提及从“整页批量转链接”升级为“选中一处预览后转换”，减少误改。别名冲突和同名页面必须展示候选及目录，不静默以扫描顺序决定用户想引用的对象。

当前 extract_links_json 基于字符串拆分，锚点只透传。后续需要用同一语义解析结果供编辑器、搜索和关系索引消费，区分真实链接与代码示例，处理路径链接、展示文本、转义与附件。旧库迁移时保留现有解析规则；对歧义给报告和可选修正，不能升级后静默换目标。Obsidian 的内部链接文档提供路径、标题、块引用与预览等参考。[Obsidian 内部链接](https://obsidian.md/help/links)。

### 6.5 记录、模板与整理（P1）

在已有每日笔记上加指定目录、日期格式、模板、历史日期导航；新建页面可选“普通笔记 / 会议 / 项目 / 读书”。收件箱通过指定目录或可筛选的状态属性表达，不必发明新文件类型。模板首版只支持固定内容和少数变量，避免先引入脚本环境。

记录 → 补链接 → 提取页面 → 加标签 → 移动/归档应可从同一页面完成。孤页不是错误，悬空目标也可能是有意记录的未来主题；允许忽略、标记待写和批量整理，别把“全无孤页”设成质量目标。

### 6.6 附件与迁移（P1，基本兼容决定试用门槛）

初期附件：粘贴图片、拖入文件、统一复制到工作区、图片/PDF 基础预览、来源链接与相对路径。移动目录应同步考虑附件路径；未知文件不会伪装成页面。不要因为附件未被当前正文引用就立刻删除，历史版本也可能需要它。Joplin 的粘贴图片与拖放附件是可参考的记录入口。[Joplin 附件](https://joplinapp.org/help/apps/attachments/)。

`.ad` 是现有产品事实，但它不应成为用户迁移现有 Markdown 库的手工负担。先做 Markdown/Obsidian 导入向导与普通 Markdown 导出：原目录、正文、frontmatter、别名、附件和链接结构均需校验，不能只改后缀。报告不支持语法、重名与歧义，原文件不被破坏。是否原生支持 `.md` 双格式需独立裁定，先做往返实验再承诺。

Logseq 导入包含块标识、缩进、属性和引用语义，复杂度更高；应在基础 Markdown 迁移可靠后增加明确支持范围。Obsidian 本身提供导入入口，迁移是产品入口的一部分。[Obsidian 导入](https://obsidian.md/help/import)。

### 6.7 属性、视图与任务（P1/P2）

先把 title/tags/aliases 做成折叠的页面内属性；未知 frontmatter 键继续保真。后续增加少量有类型的可选字段，如状态、来源、日期、项目；建立文档级列表/表格视图，筛选和排序，不立即建设数据库关系和公式系统。Notion 的视图、筛选、分组可作为组织能力参考。[Notion 视图与筛选](https://www.notion.com/help/views-filters-and-sorts)。

任务先支持标准复选框与跨页未完成清单，再按使用证据决定日期、提醒、重复任务和项目统计。不要把知识库变成复杂任务管理器。

### 6.8 探索、同步、AI 与扩展（P2/P3）

- **图谱**：先局部图，提供中心页、跳数、过滤和跳转，回答“这页与什么相关”。全库图不应遮蔽更有效的列表与上下文引用。
- **块引用**：先稳定标识与只读嵌入，后续再评估块级编辑/查询；需要处理删除、复制、移动和导出语义。
- **跨设备**：先做好外部文件变化检测、离线编辑、冲突副本和备份，再决定文件夹同步适配还是自建服务。确认手机需求时，应给手机快速记录/读取明确范围；浏览器窄屏适配不等于已有移动产品。
- **协作**：独立长期工程，包含身份、权限、评论、审计、离线冲突。当前本地编辑器不自动具备这些能力。
- **AI**：优先带来源定位的检索与摘要、标签建议和可预览的编辑差异；新增/修改内容保留人工审阅和撤销。云端调用明确内容发送范围。确定性搜索和原文始终可用。
- **扩展**：先统一命令、页面、查询、导入和面板接口，成熟后再开放插件。避免公开不稳定内部结构。

## 7. 性能与架构：不能以界面修饰掩盖承载边界

当前发布说明的 P≤200 稳定范围、500 页索引值损坏记录，属于底层正确性问题。继续做查询、图谱、批量属性之前，需要修上游或论证并验证替代承载方案。分页/虚拟列表可以改善 UI，不能修复后端字符串池值损坏。

已有缓存调查表明：150 页场景中磁盘读成本较小，跨页解析装配主导；仅做 mtime 原文缓存没有收益。这不否定将来的增量派生索引，但它应以新实验验证。建议链路：文件变化 → 语法解析 → 页面/链接/属性派生 → 一致的版本快照 → 消费面更新。索引可删除重建，原文仍是事实源。

建议记录依赖顺序：

| 底层或接口 | 解锁产品能力 | 本仓职责 |
| --- | --- | --- |
| VM 数据完整性与长调用问题 | 扩大知识库规模 | 回归语料、正确性校验、真实规模验收 |
| 编辑器命令与 save/link 事件 | 菜单有效、正文跳转、保存统一 | 宿主消费、错误状态、导航语义 |
| 光标/选区/reveal | 大纲、搜索定位、锚点引用 | 位置映射、历史返回、上下文面板 |
| 增量编辑与分块读取 | 大文档持续写作 | 保存版本协议、避免整文级重复刷新 |
| 文件监听与修订检测 | 外部编辑与同步兼容 | 脏页冲突处理、索引失效、用户反馈 |

修改应留在 Auto 单源与共享组件的正确层级。生成 Vue 只用于诊断，不是正式维护面。两轨要验证用户结果一致；无需强求每个像素一致。

文档现势注意：ARCHITECTURE 中关于 1MB 开档阻塞的部分描述与后续 benchmark 的解阻记录不完全一致，本报告不据旧描述断言当前 1MB 无法打开；每键整文回传限制仍有当前代码支撑。

## 8. 分批交付建议

P0 = 可信试用的阻碍；P1 = 日常使用闭环；P2 = 高阶复用；P3 = 长期扩展。依赖可以并行准备，但每批都应交付完整流程。

| 批次 | 内容 | 建议体量 | 完成条件 |
| --- | --- | --- | --- |
| A：可信与一致 | 重载/草稿保护、命令与事件接线、title 查找、首启工作区、导航分工、基本主题与状态 | 中；接口解锁部分高 | 不丢草稿；同一操作各入口结果一致；用户能找到眼前的标题 |
| 基础专项：承载 | VM 规模正确性、编辑/定位/监听能力表、基准口径更新 | 高，需上游 | 按逐级规模与正文大小验证正确性和持续输入，再扩大承诺范围 |
| B：日常闭环 | 自动保存与历史、搜索上下文、浏览返回、日志模板、附件、Markdown 迁移、收藏与布局恢复 | 中至高，拆成独立切片 | 捕获→整理→查找→引用→恢复→导出可全程完成 |
| C：组织复用 | 类型属性、已保存视图、任务聚合、局部图、稳定块引用 | 高 | 用真实研究/项目工作区证明节省查找与复用步骤 |
| D：跨设备与生态 | 手机记录/读取、同步、分享/协作、AI、插件 | 很高，分别立项 | 每项有用户需求、数据模型和离线/权限/迁移约定 |

最值得先拆的六个实施切片：安全重载与草稿；编辑器事件/命令接线；名称查找一致；全库导航与当前页侧栏；工作区启动与设置；搜索上下文与返回。每片有边界和可验证结果，别把一次全界面重写作为前置条件。

不估计固定周数：上游供给、开发容量和用户需求确认尚未知。上面的体量是相对复杂度，不能当排期承诺。

## 9. 验收与用户验证

### 正确性门

1. 输入后立即重载、关闭、移动、退出或模拟中断，再启动可恢复未保存正文；磁盘原文不会被恢复流程静默覆盖。
2. 外部编辑与本地脏页并存、同秒外部写入、连续自动保存迟到回执、磁盘只读/保存失败，都保留正确版本。
3. 修改显示标题后，树、快开、全文结果和标签页一致；中文/英文别名、重名、目录路径明确消歧。
4. 菜单、工具栏、快捷键和编辑器保存接入同一文档事实源；正文链接和侧栏链接都可打开正确页。
5. 导入→修改→导出保留已声明支持的正文、元数据、附件和链接，未知字段不被抹去。
6. 先测 200、500，再测 1,000/5,000/10,000 页；每级比较原文清单、链接数和目标、搜索样本、重启/增量更新。达标前不宣传未验证规模。

### 建议体验目标（待建立基线，非现有成绩）

统一硬件、release 构建、冷热状态、两条渲染轨和语料大小后，建议以 p95 衡量：热态开页/快开响应 ≤200ms；普通正文持续输入反馈 ≤50ms；1,000 页全文首批结果 ≤500ms；冷启动到可记录 ≤2s。大文档另测，不能把小文件平均值掩盖长文卡顿。目标可按真实硬件调整，正确性不能调整为容许内容损坏。

### 小规模试用

招募或邀请 5–8 位实际目标用户（建议样本，不是已完成调研），完成：首次创建库、记一条日志、建立链接、找回旧资料、移动/改名、恢复误改、导出。统计完成率、时间、误操作、求助点和一周后是否继续使用。观察要与受访者授权一致，不默认采集笔记正文。

尤其验证四个假设：文档是否是主要单位；每日记录是否是高频入口；是否已有 Markdown/Obsidian 库要迁移；手机记录是否决定用户留存。答案会影响 B/C/D 的顺序，但不影响先修保存和无效入口。
